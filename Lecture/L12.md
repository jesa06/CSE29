## **struct** datatypes
* can combine elements into one variable
* c lets you know where in memory where these variables are 
* they are in memory addresses right next to each other
* you can have an array inside of the *struct*
* you can store a function in a struct (all function is just a pointer to code of the function)
* structs go in linear order (low address up to high address)


```c
struct place { // kind of like a class 
    int latitude;
    int longitude;
    char name[64]; // Name
}

int main() {
    struct place pl; // pl is an instance of the variable
    pl.lat = 10315; // . to access the member variables 
    pl.lon = 11561;
    return 0
}
```

## passing a struct to a function 
* when i pass lat and long from struct into a function, a FULL copy is made of the entire struct into a new location of entire stack, inside the new function we just called
    * *downside* - memory inefficiency (don't need 2) AND can't modify it directly
        * original one in main function WILL NOT BE MODIFIED
* . is like the accessor to data members 

```c
long int distance(struct place p1, struct place p2) {
 // Compute the distance from p1 to p2
 return ((p1.lat – p2.lat)**2); // not actual distance
}
int main() {
 struct place dca = {389072, -770369}; //dc airport
 struct place san = {327157, -1171611}; //sd airport
 long int dist = distance(dca, san); // structs will be copied... now two copies on stack :(
}
```

## Passing a struct to a function as a ptr
* only have one copy now, modify it in place 
* treat array is a single variable, it will copy the entire array since it is contained in the single variable struct 

```c
long int distance(struct place* p1, struct place* p2) {
 // Compute the distance from p1 to p2
 return ((p1->lat – p2->lat)**2); // not actual distance
}
int main() {
 struct place dca = {389072, -770369};
 struct place san = {327157, -1171611};
 long int dist = distance(&dca, &san); // one copy only!
}
 ```

* array in C is ALWAYS a pointer
* struct is more like a single variable, pass it in with an &
* asteric to dereference then access its variable (*p1).lat
    * easier to write accessor ->

```c
#include <stdio.h>
#include <stdint.h>

#define MAX_ARGS 5

typedef struct SimpleStruct {
    char *ptr; //8 byte
    uint32_t x; // 4
    int y; // 4 

} SimpleStruct;

typedef struct ComplexStruct {
    char some_char; // 1 -> 8 bytes
    char *ptr; // 8
    char *args[MAX_ARGS]; // 8*5 = 40 bytes
    uint32_t ret; // 4 -> 8 bytes
} ComplexStruct; // 53 bytes??? + 4 + 4 = 64 bytes
                // compiler in C adds padding to 4-8 bytes 
                // faster to access in 4 byte or 8 byte chunks


typedef struct {
    char* str; 
} StringStruct

int main() {
    printf("sizeof(SimpleStruct) = %lu\n", sizeof(SimpleStruct)); //16
    printf("sizeof(ComplexStruct) = %lu\n", sizeof(ComplexStruct)); //64

    StringStruct x;
    x.str = "hello"; 
    printf("sizeof(StringStruct) = %lu\n", sizeof(StringStruct)); //8 bytes
        // treat as regular char pointer so 8
}
```
* sizeof():
    * compiler in C adds **padding** to 4-8 bytes 
    * faster to access in 4 byte or 8 byte chunks
    * if introduce int before char pointer, everything will prob be 8 bytes
    * if initialize int at end, prob leave it as 4 bytes

```c
#include <stdio.h>


struct NetworkData {
    int id; // 4 byte
    char buffer[1024]; // 1024 bytes
};

void process_data(char data_array[1024]) { //pointer
    printf("Function Size: = %zu\n", sizeof(data_array)); 
}

void process_data2(struct NetworkData x) {
    printf("Function Size: = %zu\n", sizeof(x.buffer)); 
}

int main() {
    struct NetworkData net;
    printf("Function Size: = %zu\n", sizeof(net.buffer)); // 1024 bytes
    process_data(net.buffer); // 8 bytes
    process_data2(net); // 1024

}
```

* when pass in net.buffer, it does not pass entire array, only the pointer to array 
* process_data2(net) copies entire struct into the function
