## Coalesce
> coalesce when you have 2 free allocations next to each other

* why would you want to merge 2 free allocations?
    * generate bigger area = next allocation is more likely to fit --> bigger allocations are available 
* why would you NOT want to merge 2 free allocations?
    * it takes time:
        * you must look on all neighboring sides to the current allocation to see if there are free allocations there
        * bc size of each allocation is in headers, there's a way to jump between headers (if you are going forward)
            * if you want to go backwards you may have to start from the beginning 
        * what heap design will help us go backward
            * add onto header information: previous allocation size, but now header is 16 bytes but also that contains the info stored in the previous header (store same info twice)
            * complexity, amount of code that needs to be correct is a lot higher --> much higher potential for bugs
    * store location of next free header in a header
        * helps find free allocations faster
        * BUT need to manage the updates if free or not, constantly
