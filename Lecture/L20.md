## Heap at the start
* heap is NOT infinite size...you need to start with some limit. Why?
    * so it can't run into the stack
* without heap initialized, it is blank
    * you do not have any info of the whole size of the heap
* how do i indicate that says the heap is free? 
    * header with: status "free" and size of heap
    * if num bytes even = allocation is free
    * if num bytes odd = allocation is in use 
    * initialize with bytes-8 to account for the header


1. Initialize the heap

## How do we indicate the heap is free?
1. Read first header
    * figure out if there is enough room 
        * yes --> make allocation
2. Now need a new header (replace old one) at beginning of heap for first allocation 
    * there is always a header that tells first allocation and whether it is free, every heap you maintain a *footer*
    * *footer* last header tells you how much free memory there is at the end of the heap

## How to know if an allocation is in use:
```
11101xxx
```
* last x (LSB) tells us if the allocation is in use:
    * if LSB is 1 --> allocation in use (size of allocation + 1)
    * if LSB is 0, allocation is NOT in use (size of allocation and LSB is 0)

* when you call malloc() sometimes you don't get a pointer
    * it needs to be able to give back to user to tell them they don't have enough heap size for that big of an allocation

## How do i know where in the heap i should change things?
* free(ptr2)
    * ptr points to the memory right after the header (AKA the memory you use to store data)
    * if i want to read the header, go backwards some bytes. now ready to delete the data 
    * change the LSB of header to be an even number and then it is free 
        * indicates the area of memory is available 
    * you don't actually delete the memory, it just tells machine that that space is free to be used 
        * **trade off**- zeroing out the memory will take a long time, doing it ahead of time is useless bc we don't know if we will use it again (it takes less time but you must remember that theres still data there but it may be rewritten)
* **fragmented heap**- heap with holes with free space in it
    * *downside*- may take a while to find the right size slot to store new data
* **coalesce**- the process of merging adjacent free memory blocks into a single, larger, contiguous block of memory
    * why you should NOT: it takes time (remove space, go back to change header,...)
    * why you should: wastes memory
    * something a programmer must decide on
* more allocating and freeing you do, you may be creating an area of the heap that is hard to use again, the longer the next call for malloc() will take
    * weird size in the middle of a heap
