## Hash: an integer as a fingerprint for bytes
* unique (BIG) integer that captures what bits are in THAT memory
    * maps bytes to an integer... 2^256
* one-way functions --> CANNOT BE REVERSED TO FIND THE BYTES
* useful for PWD security
* when we hash an array, we are truly hashing the bytes of memory

## The Stack
* **a function's stack frame**- When a program is running, each function that is called gets a segment of
the memory to store values
* stack stores *local variables* declared in a function (including parameters)
* stack also stores the address of where in the code a function should return to
* stack grows fit to more values from the function if needed 
* once a function is done executing, the stack frame in memory no longer belongs to the function and is able to reused for other functions

* void pointer points to anything we want (generic pointer) --> ultimately just an integer
    * tells compiler, idc what you point to just give me an address 

## Where is the Stack in memory?
* Grows down from high address to low, starts at highest memory address
* Each process (running program) gets its own stack
* **worst-case scenario that will grow the stack**- recursion (AKA THE DEVIL...requires you to use the stack)

## What happens when a function is done?
* Does a computer delete the data a function uses after its done?
    * no, there is no meaningful reason to "delete" the data. Some other code will overwrite it
* Once memory is written, it stays that value until something else overwrites it
    * this is one reason why you should always initialize variables and arrays before you use them
