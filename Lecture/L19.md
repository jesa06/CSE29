## What does malloc() do?
* when you think about stack and function calls, area of memory that you put variables is on the stack 
* where is the pointer of a malloc() in heap?
* there is no *good way* to manage the heap...important things to think about
* once you malloc() into a pointer, **YOU ARE STUCK**
* where does it store the info of how much memory is allocated 

## Malloc Implementation: Heap structure
```c
int* p1 = malloc(4); // 0x00
int* p2 = malloc(8); // 0x08
int* p3 = malloc(1); // 0x10
```
* when you call malloc() where are you going to return your pointer from the address range, ST when code uses memory, you can guarantee you don't have data overwriting each other

* put pointers at certain addresses
* managing heap is like managing a struct 
    * want to align them so they are easy/rapid to access
    * aligns bytes in structural alignment so its easier for the processor to align with 
        * processor reads (from RAM) min. size memory it can read
            * when you read only 1 byte, you are always reading 8 bytes
    * want memory to be 8 byte aligned
    * don't want to spill over and read form another allocation, 
        * if read misaligned byte, you have to throw out data and not look at it or read two times and put it back together
* **alignment requirement for 64-bit machine**:
    * 8 bytes

## Malloc Implementation: Requirements
1. only use info in the heap to manage the heap
    * store sizes of malloc in the heap (so you can call malloc as many times as you want)
2. can NOT modify previously allocated blocks
    * even if you free an allocation, you still want to know how much the region is for future allocations/storing 
        * so the sizes will be on heap all the time to keep track of this 
3. also need to store metadata in the heap about each allocation
   
## Headers: Storing metadata on the heap 
* need to waste some bytes 
    * add 8 byte headers before each allocation on the heap (8 so it is aligned nicely)
* each header has:
    * AN INTEGER that tells the size of the allocation
    * status: free or in use
* if we call malloc(1) 1000 times instead of malloc(1000) one time, 16 bytes of memory will be used to store 1 byte of memory --> **wasteful**
```c
int* p1 = malloc(4); // 0x00 header is 0-8 and info is 8 to 12 (padding 12 to )
int* p2 = malloc(8); // 0x08 header is 16-24 and info is 24 to 32
int* p3 = malloc(1); // 0x10 header is 32 to 40 and info is 32 to 33
```

## Header Implementation
* header contians a **Length** and a **flag bit** representing free/allocated
    * even num: represents a *free* block
    * odd num: represents a *malloc'd, allocated, busy block*
* In both cases, the number with LSB set to 0 is the block size in bytes
* header = 33 -> allocated block of 32 bytes (24 byte payload)
    *  don't need 3 LSB so use to contain if it is allocated or free block (one flag)
* header = 108 -> free block of 108 bytes (100 byte payload)

* always write minimum size that it is
* "size of block" = full size including header
* always make block sizes divisible by 8/8-byte aligned 
* use bit-masking to find flag is 0 or 1 (free ot not)
* use bit-masking to find the length of allocation
