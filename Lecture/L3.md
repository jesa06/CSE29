
# Lecture 3
> UTF-8 Text Representation

* UTF-8 is an extension to ASCII
* It uses variable-length encoding that's backward-compatible with ASCII

## How do we encode a char as multiple bytes?
> bit flags!

* A **code point** is an integer representing a character
* a byte in unsigned can hold up to 255
* multi-byte **code point**: highest order bit of first byte of char tells us if it is a multi-byte char
    * 1xxxxxxx
* normal ASCII **code point**
    * 0xxxxxxx
* first bits of first byte of code point dictates code point length (how many bytes it is):
    * 110xxxxx = 2 bytes
    * 1110xxxx = 3 bytes
    * 11110xxx = 4 bytes
* bytes in middle are called **continue bytes** and they start with:
    *10xxxxxx

## What do UTF-8 code points look like in memory?
* 2 byte UTF-8 has the first special byte that tells the length, and then byte 2 with the actual information (codepoint)
    * one continuing byte
* 3 byte UTF-8 has the first special byte that tells the length, and then byte 2 and byte 3 with actual information (codepoint)
    * two continuing bytes

## Code points 
* to write code point to other humans you write U+#####
    * ASCII ‘A’ is 65 which is codepoint U+0029 ()
    * Crab is codepoint (integer) 129408 which is codepoint U+1F980

* use hexadecimal to write binary data (integers...)
    * 16 options per digit (0-F) rather than 10 in decimal and 2 in binary
    * directly mapable to bits
    * compact way of representing bits because each digit represents 4 bits in memory (always) bc 2^4 = 16
    * distinguish hexadecimal numbers by prepending them with 0x........

## Code Point construction from multi-byte
* é = 0b110000110b10101001
    * 0b110 indicates 2 bytes
    * 00011 start of code point
    * 0b10 indicates continue
    * 101001 rest of code point
* code point 00011101001 = 233 = 0xE9 = U+000E9

## Analyzing codepoints requires accessing individual bits in C data types
* mathematical operators in C for doing operations on bits 
    * & AND
    * | OR
    * ^ XOR
    * >> Shift right
    * << Shift left

### Or
* let's you change bits
* will not let you make something 0 
* Or is a **bit setter or turn-on device**
* you can only ADD bits 
    * thath's why we can use or to go from lowercase to uppercase

### Bit operations to do uppercase()
* subtraction is needed to go from lowercase to uppercase (-32)

### And
> bit GETTER

* you can choose what bits of the number you want to get out
* mask indicates that we apply a mask (masking out the bit we want)
* **masking** is selecting specific individual bits out of a binary representation of a number
